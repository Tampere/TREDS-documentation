# Tampere Design System (TREDS) documentation

Private documentation site for the Tampere Design System (TREDS), built with [Docusaurus](https://docusaurus.io/).
It serves designers, developers, product owners, service designers and procurement teams working with digital services in the City of Tampere.

> **All content is draft placeholder/template content.** It does not contain official TREDS guidelines. Replace placeholders with documented guidelines as they are agreed.

## Structure

```
docs/                 Documentation (Markdown), one folder per section
  getting-started/    What is TREDS, who should use it, principles, adoption
  foundations/        Colors, typography, spacing, icons, accessibility
  components/         Overview, usage guidelines, do's and don'ts, accessibility
  design/             Figma resources, design workflows, design reviews
  development/        Installation, repository structure, Storybook, releases
  accessibility/      WCAG compliance guidance, testing checklist
  governance/         Roles, contribution model, versioning principles
  procurement/        Supplier requirements, using TREDS in purchased services
src/pages/            Landing page
static/               Static assets (logo, favicon, Azure SWA config)
docusaurus.config.js  Site, navbar, footer and search configuration
sidebars.js           Sidebar (autogenerated from the docs folder structure)
```

Sidebar order is controlled by `sidebar_position` in page front matter and `position` in each `_category_.json`.

## Local development

Requires Node.js 20 or newer.

```bash
npm install
npm start        # dev server at http://localhost:3000/TREDS-documentation-TEST/
npm run build    # production build to ./build
npm run serve    # serve the production build locally
```

Search uses [`@easyops-cn/docusaurus-search-local`](https://github.com/easyops-cn/docusaurus-search-local). The search index is generated at build time, so search works in `npm run build` + `npm run serve`, not in `npm start`.

## Publishing

The site URL and base path are set with environment variables (defaults target GitHub Pages):

| Variable | Default |
| --- | --- |
| `DOCS_URL` | `https://tampere.github.io` |
| `DOCS_BASE_URL` | `/TREDS-documentation-TEST/` |

### GitHub Pages

`.github/workflows/deploy.yml` builds and deploys on every push to `main`. In the repository settings, set **Pages > Source** to **GitHub Actions**. Note that Pages for private repositories requires a plan that supports private Pages and access control; confirm that access is restricted to the intended audience.

### Azure Static Web Apps

1. Create a Static Web App and connect it to this repository.
2. Use build preset **Custom**: app location `/`, output location `build`, build command `npm run build`.
3. Set `DOCS_URL` to the Static Web App URL and `DOCS_BASE_URL` to `/` as build environment variables.
4. Restrict access (for example with Microsoft Entra ID authentication) in `staticwebapp.config.json` routes, since this is a private site.

`static/staticwebapp.config.json` is included in the build output and adds a `noindex` header. The site also sets `noIndex: true` in the Docusaurus config so search engines are asked not to index it.

## Contributing content

1. Edit or add Markdown files under `docs/`.
2. Keep all content in English.
3. Keep the `Draft content` notice on a page until its content has been reviewed and approved, then remove it.
4. Run `npm run build` to check for broken links before opening a pull request.
