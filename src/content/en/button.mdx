# Button

A button triggers an action on the current page: saving, submitting or opening a dialog.

<ComponentLinks name="Button" lang="en" />

<Example name="button/Hero" lang="en" />

## When to use

Use a button when the action happens on this page: submitting a form, saving, opening a dialog or clearing filters.

**Don't use a button when**

- activating it takes the user to another page – use <ComponentRef name="TextLink" lang="en" />
- the user selects or filters options – use <ComponentRef name="Chip" lang="en" />
- it is an icon action in the site header – use <ComponentRef name="IconButton" lang="en" /> or <ComponentRef name="LabeledIconButton" lang="en" />

## Variants and situations

### Emphasis

Use at most one primary button per view, so the main action stands out. Secondary is for alternatives such as saving a draft or cancelling, placed after the primary button. Tertiary is for low-emphasis actions such as showing more content.

<Example name="button/Emphasis" lang="en" />

### Rounded

`radius="pill"` rounds the button's ends fully. It belongs to TREDS's rounded style, meant for services whose look and feel is rounded. Don't mix rounded and sharp buttons within one service.

<Example name="button/Pill" lang="en" />

### Icons

An icon supports the label and doesn't replace it. An icon that points a direction belongs on the right. Use an icon-only button only for well-established actions such as search.

<Example name="button/WithIcons" lang="en" />

## Accessibility

- Say what happens, even out of context: "Submit application", not "OK". On an icon-only button, say it with `aria-label`.
- Don't use a button to move to another page. Screen readers announce it as a button, and users expect an action.
- Prefer an enabled button that tells the user what is missing over a disabled one. A disabled button is removed from the focus order, so screen reader users may not find it.
