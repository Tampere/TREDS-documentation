# Checkbox

<ComponentBadges name="Checkbox" lang="en" />

A checkbox lets the user select one or more options, or confirm a single thing.

<ComponentLinks name="Checkbox" lang="en" />

<Example name="checkbox/Hero" lang="en" />

## When to use

Use checkboxes when the user can select any number of options, including none. A single checkbox suits a yes/no choice that is saved with the form.

**Don't use a checkbox when**

- the user may select only one option – use <ComponentRef name="RadioButton" lang="en" />
- the setting takes effect immediately, without submitting a form – use <ComponentRef name="Switch" lang="en" />
- the user filters content on the page – use <ComponentRef name="Chip" lang="en" />

## Variants and situations

### Checkbox group

Group related checkboxes with <ComponentRef name="Fieldset" lang="en" />, as in the example at the top of the page. `legend` states the question, and the `fieldsetSelectionGroup` class stacks the checkboxes with the right spacing.

### Single checkbox

A single checkbox doesn't need a group. Its label alone says what the choice means.

<Example name="checkbox/Single" lang="en" />

### Select all

`indeterminate` shows the checkbox as partly selected. Use it on a "select all" checkbox when only some of the options below it are selected. The component doesn't work out the state itself: derive `checked` and `indeterminate` from the options below.

<Example name="checkbox/SelectAll" lang="en" />

### Error

`error` colours the checkbox in the error colour but shows no message. Give the group an error message with Fieldset's `error` prop and set `aria-invalid` on the checkboxes.

<Example name="checkbox/Error" lang="en" />

### Disabled

`disabled` prevents selection and greys out the label. A disabled checkbox can't be focused with the keyboard, so explain elsewhere why the choice isn't available.

<Example name="checkbox/Disabled" lang="en" />

## Content guidelines

- Write the label in the positive: "Send a confirmation to my email", not "Don't send a confirmation".
- Phrase the group's `legend` as a question that the options answer.
- Order the options logically, for example alphabetically or from most to least common.
- Avoid links in the label. Give terms or further information above the checkbox.

## Accessibility

**The component handles**

- The checkbox is a native `<input type="checkbox">`, and `label` is its `<label>`. Screen readers read the label as the checkbox's name, and clicking the label toggles the choice.
- Space toggles the choice, and a focused checkbox gets the TREDS focus ring.
- `indeterminate` sets `aria-checked="mixed"`, so screen readers announce the partial selection.
- The selection also shows as the icon's shape, not only as colour.

**Your responsibility**

- Group related checkboxes with Fieldset, so the group has a name screen readers announce.
- Always give an error message with Fieldset's `error` prop.
- When a form is submitted with errors, move focus to the first invalid field or to an error summary.
- If at least one option in a group must be selected, check it yourself: native `required` requires each checkbox separately. Mark the group with Fieldset's `showRequiredMarker` prop and state the requirement with `helperText`.
- Derive a "select all" checkbox's `checked` and `indeterminate` from the options below, so the state screen readers announce is correct.

WCAG criteria: [1.3.1 Info and Relationships](https://www.w3.org/WAI/WCAG21/Understanding/info-and-relationships.html), [1.4.1 Use of Color](https://www.w3.org/WAI/WCAG21/Understanding/use-of-color.html), [3.3.1 Error Identification](https://www.w3.org/WAI/WCAG21/Understanding/error-identification.html), [3.3.2 Labels or Instructions](https://www.w3.org/WAI/WCAG21/Understanding/labels-or-instructions.html), [4.1.2 Name, Role, Value](https://www.w3.org/WAI/WCAG21/Understanding/name-role-value.html)
