# Fieldset

<ComponentBadges name="Fieldset" lang="en" />

Fieldset groups related form fields under a shared legend.

<ComponentLinks name="Fieldset" lang="en" />

<Example name="fieldset/Hero" lang="en" />

## When to use

Use a fieldset when fields together answer one question or form a whole, such as contact details or an address. Checkbox and radio button groups always need a fieldset.

**Don't use a fieldset when**

- you ask a single thing with a single field – the field's own label is enough
- you only want to split a long form into parts without a shared question – use subheadings

## Variants and situations

### Checkbox and radio button group

Wrap the group's <ComponentRef name="Checkbox" lang="en">checkboxes</ComponentRef> or <ComponentRef name="RadioButton" lang="en">radio buttons</ComponentRef> in an element with the `fieldsetSelectionGroup` class. The class stacks them with a tighter gap than separate fields.

### Required group and helper text

`showRequiredMarker` adds an asterisk after the legend and `helperText` shows guidance below it. The asterisk is visual only, so state the requirement in the helper text too.

<Example name="fieldset/Required" lang="en" />

### Error

`error` shows the group's error message below the helper text. Use it for errors that concern the whole group, such as "choose at least one". An error in a single field belongs to that field. Remove the error once it is fixed.

<Example name="fieldset/Error" lang="en" />

### Border

`withBorder` draws a border around the group. There is no border by default.

<Example name="fieldset/WithBorder" lang="en" />

## Content guidelines

- Keep the legend short. For choice groups, phrase it as a question that the options answer.
- Don't repeat the legend's words in every field label: "Contact details" and "Email", not "Contact details email".
- Say in the group's error message what is wrong and how to fix it.

## Accessibility

**The component handles**

- The fieldset is a native `<fieldset>`, and `legend` is its `<legend>`. Screen readers announce the group's name when the user moves into its fields.
- The helper text and the error message are linked to the group with `aria-describedby`.
- The required asterisk is hidden from screen readers.

**Your responsibility**

- State the requirement in text. Screen readers don't hear the asterisk, and a checkbox group has no native way to be required. Mark individual required fields with their own `required` prop.
- Not every screen reader reads the group's description. Don't leave essential information only in the helper text or error message: when a form is submitted with errors, move focus to the first invalid field or to an error summary.
- Set `aria-invalid` on the invalid checkboxes and radio buttons, so screen readers say which of the group's fields the error concerns. TextField doesn't accept `aria-invalid` but sets it from its own `error` prop, so give an invalid text field its own error message.

WCAG criteria: [1.3.1 Info and Relationships](https://www.w3.org/WAI/WCAG21/Understanding/info-and-relationships.html), [3.3.1 Error Identification](https://www.w3.org/WAI/WCAG21/Understanding/error-identification.html), [3.3.2 Labels or Instructions](https://www.w3.org/WAI/WCAG21/Understanding/labels-or-instructions.html)
