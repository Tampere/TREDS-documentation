# FileInput

<ComponentBadges name="FileInput" lang="en" />

A file input lets the user attach files to a form. The selected files are listed below the field, and each one can be removed.

<ComponentLinks name="FileInput" lang="en" />

<Example name="file-input/Hero" lang="en" />

## When to use

Use a file input when the form has little space or the attachment is secondary, for example an optional attachment to feedback.

**Don't use a file input when**

- the attachments are central to the form or the user attaches several files – use <ComponentRef name="Dropzone" lang="en" />. It is the recommended way to attach files in TREDS, because files can also be dragged onto it.
- you show files that were already saved, without a picker – use <ComponentRef name="FileList" lang="en" />

## Variants and situations

### One file

By default one file is selected. A new choice replaces the previous one. The file name shows in the field and in the list below it, where it can be removed.

`accept` limits the file types and `maxSize` the size in bytes, as in the example at the top of the page. The component rejects other files and shows an error message. Also state the limits in the help text, so the user knows them before choosing.

### Several files

`multiple` allows more than one file, and new choices are added to the list. `maxFiles` limits the count. The field shows how many files are selected, and the files are listed below it.

<Example name="file-input/Multiple" lang="en" />

### Sending the files

The file input does not take part in a normal form submission: it has no `name` prop, and the browser's own file input does not keep the selection. Hold the files in state with `value` and `onChange` and send them yourself, for example in a `FormData` object.

<Example name="file-input/Send" lang="en" />

### Error

`error` shows your own error message, for example when the upload to the server fails. It overrides the component's own rejection message.

<Example name="file-input/Error" lang="en" />

### Disabled

`disabled` prevents choosing and removing files. A disabled button can't be focused with the keyboard, so explain why in the help text.

<Example name="file-input/Disabled" lang="en" />

## Content guidelines

- Name the label after what is attached: "Attachment", "Photos", "Site plan".
- State the allowed file types, the maximum size and the maximum count in the help text.
- **All built-in texts are Finnish**, including the rejection messages. On an English page, pass `buttonLabel`, `placeholder`, `removeLabel`, `selectedCountLabel` and `rejectionMessage`, as the examples on this page do.

## Accessibility

**The component handles**

- The picker button is named by the label and its own text, for example "Attachment Choose file". Clicking the label opens the picker.
- The help text, the error message and the selection status are connected to the button with `aria-describedby`, and an error sets `aria-invalid="true"`.
- The selection status ("site-plan.pdf", "2 files chosen") is a `role="status"` region, so screen readers announce changes.
- Each remove button's name includes the file name, for example "Remove file: site-plan.pdf". After a removal, focus moves to the next remove button or, if the list empties, to the picker button.

**Your responsibility**

- Always give the field an `inputLabel`. If that isn't possible, give `aria-label`.
- State the file limits in the help text before the user chooses.

WCAG criteria: [1.3.1 Info and Relationships](https://www.w3.org/WAI/WCAG21/Understanding/info-and-relationships.html), [3.3.1 Error Identification](https://www.w3.org/WAI/WCAG21/Understanding/error-identification.html), [3.3.2 Labels or Instructions](https://www.w3.org/WAI/WCAG21/Understanding/labels-or-instructions.html), [4.1.3 Status Messages](https://www.w3.org/WAI/WCAG21/Understanding/status-messages.html)
