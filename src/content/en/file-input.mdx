# FileInput

<ComponentBadges name="FileInput" lang="en" />

A file input lets the user attach files to a form. The selected files are listed below the field, and each one can be removed.

<ComponentLinks name="FileInput" lang="en" />

<Example name="file-input/Hero" lang="en" />

## When to use

Use a file input when the form has little space or the attachment is secondary, for example an optional attachment to feedback.

**Don't use a file input when**

- the attachments are central to the form or the user attaches several files – use <ComponentRef name="Dropzone" lang="en" />. It is the recommended way to attach files in TREDS, because files can also be dragged onto it.
- you show files that were already saved, without a picker – use <ComponentRef name="FileList" lang="en" />

## Variants and situations

### One or several files

By default one file is selected, and a new choice replaces the previous one. `multiple` allows more than one file, and new choices are added to the list. `maxFiles` limits the count. `accept` limits the file types and `maxSize` the size in bytes, as in the example at the top of the page. The component rejects other files and shows an error message.

<Example name="file-input/Multiple" lang="en" />

### Sending the files

The file input does not take part in a normal form submission: it has no `name` or `form` prop, and the browser's own file input does not keep the selection. Hold the files in state with `value` and `onChange` and send them yourself, for example in a `FormData` object.

<Example name="file-input/Send" lang="en" />

## Accessibility

- Always give the field an `inputLabel`. If that isn't possible, give `aria-label`. Name the label after what is attached: "Attachment", "Photos", "Site plan".
- State the allowed file types, the maximum size and the maximum count in the help text before the user chooses.
- All built-in texts are Finnish, including the rejection messages. On an English page, pass `buttonLabel`, `placeholder`, `removeLabel`, `selectedCountLabel` and `rejectionMessage`, as the examples on this page do.
- Use `error` for your own error message, for example when the upload to the server fails. It overrides the component's own rejection message.
- When the file input is `disabled`, explain why in the help text. A disabled button can't be focused with the keyboard.
