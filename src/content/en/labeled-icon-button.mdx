## When to use

Use a labeled icon button in toolbars and in the app header's actions, when the icon alone doesn't make the action clear enough but there's no room for a regular button.

**Don't use a labeled icon button when**

- the icon is unambiguous and space is tight, for example in a table row – use <ComponentRef name="IconButton" lang="en" />
- it is the view's main action – use <ComponentRef name="Button" lang="en" />
- the text doesn't fit in one or two words – use a <ComponentRef name="Button" lang="en" /> with an icon

## Variants and situations

### On a dark background

`variant="inverted"` makes the icon and the label light. Use it only on a dark or coloured background.

<Example name="labeled-icon-button/Inverted" lang="en" />

### As a link

`renderRoot` swaps the root element, for example for a router link. The icon and label stay.

<Example name="labeled-icon-button/RouterLink" lang="en" />

## Accessibility

- Write the `label` so that it states the action even without the icon. Use one word, preferably a verb: "Edit", "Download", "Delete".
- Use the same icon and label for the same action across the service.
- For a button used as a link, the label names the destination: "Home", not "Go".
- Don't set `aria-label` or `aria-labelledby`: the visible `label` is always the accessible name.
- A disabled button can't be focused with the keyboard, so explain elsewhere why the action isn't available.
