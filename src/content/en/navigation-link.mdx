# NavigationLink

<ComponentBadges name="NavigationLink" lang="en" />

A navigation link takes the user to another page of the service from a navigation, and shows which page the user is on.

<ComponentLinks name="NavigationLink" lang="en" />

<Example name="navigation-link/Hero" lang="en" />

## When to use

Use navigation links in link lists that move the user between the service's pages: section navigation, the footer and your own navigation menus. <ComponentRef name="AppHeader" lang="en" /> and <ComponentRef name="Footer" lang="en" /> already use it.

**Don't use a navigation link when**

- the link is in the middle of body text – use <ComponentRef name="TextLink" lang="en" />
- the link highlights content that has a title and a description – use <ComponentRef name="Linkbox" lang="en" />
- pressing it does something on the current page – use <ComponentRef name="Button" lang="en" />
- you show the page's place in the hierarchy – use <ComponentRef name="Breadcrumbs" lang="en" />

## Variants and situations

### Link list

A navigation link is an inline element with no spacing of its own. Lay the links out yourself, for example with flex and a TREDS spacing token, as in the examples. Without a layout the links sit on one line with no gaps.

### Current page

`isSelected` underlines the link and sets `aria-current="page"` on it, as in the example at the top of the page. Mark only one link per navigation as selected.

### Small size

`size="sm"` is smaller and lighter. Use it for secondary link lists, like the footer's legal links.

<Example name="navigation-link/Small" lang="en" />

### Icons

`startIcon` adds an icon before the text and `endIcon` after it. The icon is always 18px, whatever the size.

<Example name="navigation-link/WithIcons" lang="en" />

### On a dark background

`variant="inverted"` makes the text, the underline and the focus ring light. Use it only on a dark or coloured background.

<Example name="navigation-link/Inverted" lang="en" />

### Router link

`renderLink` replaces the default `<a>` element, for example with Next.js's `Link`. The function gets the class and the `aria-current` value, and you must apply them yourself. `href`, `startIcon` and `endIcon` don't work with `renderLink`: give the address and the icons to your own element.

<Example name="navigation-link/RouterLink" lang="en" />

## Content guidelines

- Write the link text as the name of the target page: "Housing advice", not "Read more".
- Use the same name in the link and in the target page's heading.

## Accessibility

**The component handles**

- A navigation link is a native `<a>` element, so it works with the keyboard and the browser's link features.
- `isSelected` sets `aria-current="page"`, so screen readers announce the current page. The selection shows as an underline, not by colour alone.
- A focused link gets the TREDS focus ring. In the `inverted` variant the ring is light.

**Your responsibility**

- Wrap navigation links in a `<nav>` element and give it an `aria-label` that tells it apart from the page's other navigations.
- Always give `href` or `renderLink`. Without them the link is an `<a>` with no address: it can't be focused, and screen readers don't recognise it as a link.
- With `renderLink`, set the `aria-current` the function receives on your own element. Otherwise the current page isn't announced.
- Give `startIcon` and `endIcon` icons `aria-hidden`, as in the example.

WCAG criteria: [1.1.1 Non-text Content](https://www.w3.org/WAI/WCAG21/Understanding/non-text-content.html), [1.3.1 Info and Relationships](https://www.w3.org/WAI/WCAG21/Understanding/info-and-relationships.html), [2.4.4 Link Purpose (In Context)](https://www.w3.org/WAI/WCAG21/Understanding/link-purpose-in-context.html), [2.4.7 Focus Visible](https://www.w3.org/WAI/WCAG21/Understanding/focus-visible.html), [4.1.2 Name, Role, Value](https://www.w3.org/WAI/WCAG21/Understanding/name-role-value.html)
