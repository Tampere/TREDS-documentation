# Pagination

<ComponentBadges name="Pagination" lang="en" />

Pagination splits a long list or table into pages. Users move between pages with the numbers or the previous and next buttons.

<ComponentLinks name="Pagination" lang="en" />

<Example name="pagination/Hero" lang="en" scroll />

## When to use

Use Pagination when a list or a <ComponentRef name="Table" lang="en">table</ComponentRef> is too long for one view and the user looks for a particular item in it, for example in search results.

**Don't use Pagination when**

- there is only one page – hide the pagination altogether
- the user browses the content from start to end – show it all or add a "Show more" button
- the user moves through a form step by step

## Variants and situations

### You own the state

Pagination keeps no state of its own. **Indexes start at zero:** the first page is `0`, even though its button reads 1. The buttons are `<button>` elements, not links. If the pages have their own URLs, update the URL yourself in `onPageChange`.

### When the page changes

When the page changes, move focus to the content's heading. Keyboard and screen reader users then start the new page from the top. In the example the heading has `tabIndex={-1}` so it can be focused from code. The heading also states the page number.

<Example name="pagination/Results" lang="en" scroll />

## Accessibility

- Name the page buttons with `getAriaLabelForButton`, for example "Page 3 of 10". Without it their names are bare numbers.
- Name the arrow buttons "Previous page" and "Next page" with `leftButtonLabel` and `rightButtonLabel`.
- Say in or below the content's heading which page the user is on and how many results there are in total.
- Move focus to the content's heading when the page changes.
- Check the pagination on a 320px wide screen.
