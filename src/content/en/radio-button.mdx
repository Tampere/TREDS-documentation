# RadioButton

<ComponentBadges name="RadioButton" lang="en" />

Radio buttons let the user choose one option out of several.

<ComponentLinks name="RadioButton" lang="en" />

<Example name="radio-button/Hero" lang="en" />

## When to use

Use radio buttons when the user must choose exactly one option, and there are few enough options to show them all at once.

**Don't use radio buttons when**

- the user can choose more than one option – use <ComponentRef name="Checkbox" lang="en" />
- you ask for a single yes/no confirmation – use a single <ComponentRef name="Checkbox" lang="en" />
- there are so many options that the list would take up too much space – use <ComponentRef name="Select" lang="en" />

## Variants and situations

### Radio button group

Radio buttons always come in a group. Group them with <ComponentRef name="Fieldset" lang="en" />, as in the example at the top of the page: `legend` states the question, and the `fieldsetSelectionGroup` class stacks the options. Give the group's radio buttons the same `name`.

Keep the selected value in state and give each radio button `checked` and `onChange`.

### Error

`error` colours the radio button in the error colour but shows no message. Give the group an error message with Fieldset's `error` prop and set `aria-invalid` on the radio buttons. Remove the error once the user chooses an option.

<Example name="radio-button/Error" lang="en" />

### Disabled

`disabled` prevents choosing a single option and greys out its label. Explain in the group's helper text why the option isn't available, because a disabled radio button can't be focused with the keyboard.

<Example name="radio-button/Disabled" lang="en" />

## Content guidelines

- Phrase the group's `legend` as a question that the options answer.
- Keep the options short and parallel, for example "By email", "By phone", "By letter".
- Order the options logically, for example along a scale or from most to least common.
- Preselect an option only when it is a safe default. If the user must make a deliberate choice, leave all unselected.

## Accessibility

**The component handles**

- The radio button is a native `<input type="radio">`, and `label` is its `<label>`. Screen readers read the label as the radio button's name, and clicking the label selects the option.
- Within a group sharing a `name`, the arrow keys move the selection, and Tab enters the group at the selected option.
- A focused radio button gets the TREDS focus ring.
- The selection also shows as the icon's shape, not only as colour.

**Your responsibility**

- Group radio buttons with Fieldset, so the group has a name screen readers announce.
- Give each group its own `name`. Groups on the same page that share a `name` act as one group in the browser, so the selection and the arrow keys jump from one group to the other.
- Give every radio button a `label`. TypeScript doesn't require it, but without one the radio button has no name unless it gets an `aria-label`.
- Always give an error message with Fieldset's `error` prop.
- When a form is submitted with errors, move focus to the first invalid field or to an error summary.

WCAG criteria: [1.3.1 Info and Relationships](https://www.w3.org/WAI/WCAG21/Understanding/info-and-relationships.html), [1.4.1 Use of Color](https://www.w3.org/WAI/WCAG21/Understanding/use-of-color.html), [2.1.1 Keyboard](https://www.w3.org/WAI/WCAG21/Understanding/keyboard.html), [3.3.1 Error Identification](https://www.w3.org/WAI/WCAG21/Understanding/error-identification.html), [3.3.2 Labels or Instructions](https://www.w3.org/WAI/WCAG21/Understanding/labels-or-instructions.html), [4.1.2 Name, Role, Value](https://www.w3.org/WAI/WCAG21/Understanding/name-role-value.html)
