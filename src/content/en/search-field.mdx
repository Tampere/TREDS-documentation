# SearchField

<ComponentBadges name="SearchField" lang="en" />

A search field lets the user type a search term and pick a suggestion from a list. The search button or picking a suggestion starts the search.

<ComponentLinks name="SearchField" lang="en" />

<Example name="search-field/Hero" lang="en" />

## When to use

Use a search field when the user looks for one item in a large set and you know the items that can be chosen, for example a service, a street or a library.

**Don't use a search field when**

- there are few options, under twenty or so – use <ComponentRef name="Select" lang="en" />
- the search uses free text, like a site-wide text search – the search field only searches with a suggestion picked from the list (#229). Use <ComponentRef name="TextField" lang="en" /> and your own search button in a form.

## Variants and situations

### Suggestions

The search field doesn't filter suggestions itself. Read the typed text with `onChange`, filter or fetch the suggestions and pass them to `data`, as in the example at the top of the page. The part of a suggestion that matches the search term is shown in bold. The list opens when `data` is not empty.

The search only starts once the user has picked a suggestion and presses the search button. `onSearch` receives the picked suggestion. Typed text alone doesn't start a search, and Enter does nothing without a picked suggestion.

### Search on selection

`searchOnItemSelect` starts the search as soon as the user picks a suggestion, so the search button isn't needed.

<Example name="search-field/SearchOnSelect" lang="en" />

### Loading

When suggestions are fetched from a server, `isLoading` shows a loading animation in the list while the request runs.

<Example name="search-field/Loading" lang="en" />

### Custom suggestion content

`labelElement` replaces a suggestion's visible content, for example with extra information on a second line. Screen readers still read only the `label` text.

<Example name="search-field/CustomOption" lang="en" />

### Without a visible label

In a site header the search field usually has no visible label. Pass `aria-label` instead, as in the multi-row layout of <ComponentRef name="AppHeader" lang="en" />. `fillAvailableSpace` stretches the field to the full width.

<Example name="search-field/NoVisibleLabel" lang="en" />

## Content guidelines

- Say in the label what is searched for: "Search for a service", "Street address".
- If suggestions only appear after a few letters, say so in the help text.
- If the page has more than one search field, give each search button a name that says what it searches.

## Accessibility

**The component handles**

- `inputLabel` is the field's `<label>`. The search button's name comes from `searchButtonLabel` and the clear button's from `clearButtonLabel`. Both are required.
- The suggestions are in a `listbox`. The arrow keys move between suggestions, Enter picks one and Esc closes the list.
- Each suggestion is named by its `label` and tells its position in the list, for example "1 / 5".

**Your responsibility**

- Give the field a visible `inputLabel`. Without it, pass `aria-label`.
- Announce the result or move to the results page in your `onSearch` handler. The search field announces nothing itself.
- The field lacks the `combobox` role and `aria-expanded`, so screen readers don't announce that the suggestion list opened (#194).
- The loading animation has no name, so screen readers don't announce loading (#219).
- The clear button disappears when the field empties, and focus drops to the start of the page (#191).
- When you use `labelElement`, make sure `label` alone tells the suggestions apart.

WCAG criteria: [1.3.1 Info and Relationships](https://www.w3.org/WAI/WCAG21/Understanding/info-and-relationships.html), [2.1.1 Keyboard](https://www.w3.org/WAI/WCAG21/Understanding/keyboard.html), [2.4.3 Focus Order](https://www.w3.org/WAI/WCAG21/Understanding/focus-order.html), [4.1.2 Name, Role, Value](https://www.w3.org/WAI/WCAG21/Understanding/name-role-value.html)
