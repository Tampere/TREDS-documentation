# Select

<ComponentBadges name="Select" lang="en" />

A dropdown for choosing one option. The list can be filtered by typing, and options can be grouped.

<ComponentLinks name="Select" lang="en" />

<Example name="select/Hero" lang="en" />

## When to use

Use a select when the user picks one option from a list that is too long to show at once, such as a district or a service. Order the options logically: alphabetically, or by their meaning if the order matters.

**Don't use a select when**

- there are only a few options – use <ComponentRef name="RadioButton" lang="en" />, so all options are visible at once
- the user can pick more than one option – use <ComponentRef name="Checkbox" lang="en" /> or <ComponentRef name="Chip" lang="en" />
- the answer is free text – use <ComponentRef name="TextField" lang="en" />
- the choice takes the user to another page – use links

## Variants and situations

### Grouped options

`options` also accepts groups: `{ group, items }`. The group's heading shows above its options in the list and can't be selected. Use groups when the options fall into clear categories, and keep the group names short.

<Example name="select/Grouped" lang="en" />

### Search

Typing always filters the list. `showSearchIcon` adds a search icon that signals this. Always write a `noResultsMessage` when the list can be filtered. Without it the list is empty.

<Example name="select/Search" lang="en" />

### Value in state

When the selection is in state, pass `value` and `onChange`. Note that `onChange` is also called while typing, with the typed text, not only when an option is chosen. Check that the value is one of the options.

<Example name="select/Controlled" lang="en" />

## Accessibility

- Always give a visible `inputLabel`. Keep it short and say what is chosen: "District", not "Choose a district from the list".
- Set `clearButtonLabel`, `expandButtonLabel` and `collapseButtonLabel`, so the buttons have names.
- In the `error` message, say what the user needs to do.
