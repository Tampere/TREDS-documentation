# Table

<ComponentBadges name="Table" lang="en" />

Table shows data in rows and columns that can be read and compared in both directions.

## When to use

Use a table when the items share the same attributes and the user compares them, for example opening hours or application statuses.

**Don't use a table when**

- you only want to place content side by side – use CSS layout
- each item has only one piece of data – use a list
- the items differ in content and link onwards – use <ComponentRef name="Card" lang="en" /> or <ComponentRef name="Linkbox" lang="en" />

## Variants and situations

### Structure

Table is made of parts that match the HTML table elements: `Table`, `TableHeader` (`<thead>`), `TableBody` (`<tbody>`), `TableRow` (`<tr>`), `TableHeaderCell` (`<th>`) and `TableCell` (`<td>`). Give every header cell a `scope`: `col` for a column header and `row` for a row header. A row header gets a line on its right edge.

### Title

The `title` of `TableHeader` is shown above the table as a `<caption>` and is the table's name, as in the example at the top of the page. If a heading already sits above the table, name the table with `aria-label` on `Table`.

### Wide table

Table doesn't scroll itself. A wide table overflows the page, so wrap it in a scrollable element. Give the wrapper `tabIndex={0}` so it can be scrolled with the keyboard, plus `role="region"` and a name.

<Example name="table/Scroll" lang="en" />

### Pagination

A long table can be split into pages with <ComponentRef name="Pagination" lang="en" />. Put it after the table in a `TableFooter` with `variant="div"`. State the page number in the table's title, and move focus when the page changes, as the <ComponentRef name="Pagination" lang="en">Pagination page</ComponentRef> explains.

<Example name="table/WithPagination" lang="en" />

## Content guidelines

- Keep column headers short and unambiguous.
- Don't leave cells empty. Write, for example, "Closed" or "No data".
- Keep the number of columns low. If there is a lot of data, consider whether the user needs all of it.

## Accessibility

**The component handles**

- Table is an HTML table, and the `title` of `TableHeader` is its name.
- Rows are separated by lines and header cells are bold, so the structure doesn't rely on colour alone.

**Your responsibility**

- Name the table: `title` or `aria-label`.
- Give every header cell a `scope`.
- Wrap a wide table in a scrollable region with a name and `tabIndex={0}`.
- Every row changes its background under the mouse, even though it can't be clicked. Don't let that mislead users: for example, don't write "click a row".

WCAG criteria: [1.3.1 Info and Relationships](https://www.w3.org/WAI/WCAG21/Understanding/info-and-relationships.html), [1.4.10 Reflow](https://www.w3.org/WAI/WCAG21/Understanding/reflow.html), [2.1.1 Keyboard](https://www.w3.org/WAI/WCAG21/Understanding/keyboard.html), [4.1.2 Name, Role, Value](https://www.w3.org/WAI/WCAG21/Understanding/name-role-value.html)
