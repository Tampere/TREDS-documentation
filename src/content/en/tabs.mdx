# Tabs

<ComponentBadges name="Tabs" lang="en" />

Tabs let the user switch between parallel views of content on the same page.

<ComponentLinks name="Tabs" lang="en" />

<Example name="tabs/Hero" lang="en" />

## When to use

Use tabs when content splits into a few parallel views that users don't need at the same time, for example the different areas of one service.

**Don't use tabs when**

- users need to compare the views' content – show the content one after another
- the sections are independent and users need only some of them – use <ComponentRef name="Accordion" lang="en" />
- a tab would go to another page – use <ComponentRef name="NavigationLink" lang="en" />
- the user moves through a step-by-step form

## Variants and situations

### Structure

Tabs has four parts: `Tabs` holds the state, `TabsList` contains the tabs, `TabsTab` is one tab and `TabsPanel` its content. A tab and its panel are paired with the same `value`. `defaultValue` selects the tab shown first, as in the example at the top of the page. To keep the selected tab in state, for example in the URL, use `value` and `onChange`.

### Scrollable tabs

Without `scrollable` the tabs don't wrap, so use it whenever there are many tabs or long names. Arrow buttons then appear when the tabs don't fit on one row. `align` (`left`, `center` or `right`) aligns the tab group.

<Example name="tabs/Scrollable" lang="en" />

### Tab names

Give tabs short names of one or two words, and keep them parallel: "Borrowing, Events, Rooms", not "Borrowing, See events". With more than five tabs, consider another structure.

## Accessibility

- Give `TabsList` an `aria-label` that says what the tabs are about.
- If the page isn't in Finnish, give the scroll buttons names with `scrollLeftLabel` and `scrollRightLabel`.
- If a panel has no focusable content, the Tab key skips it. Make sure the panel's content can also be found in a screen reader's browse mode.
