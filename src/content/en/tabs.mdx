# Tabs

<ComponentBadges name="Tabs" lang="en" />

Tabs let the user switch between parallel views of content on the same page.

<ComponentLinks name="Tabs" lang="en" />

<Example name="tabs/Hero" lang="en" />

## When to use

Use tabs when content splits into a few parallel views that users don't need at the same time, for example the different areas of one service.

**Don't use tabs when**

- users need to compare the views' content – show the content one after another
- the sections are independent and users need only some of them – use <ComponentRef name="Accordion" lang="en" />
- a tab would go to another page – use <ComponentRef name="NavigationLink" lang="en" />
- the user moves through a step-by-step form

## Variants and situations

### Structure

Tabs has four parts: `Tabs` holds the state, `TabsList` contains the tabs, `TabsTab` is one tab and `TabsPanel` its content. A tab and its panel are paired with the same `value`. `defaultValue` selects the tab shown first, as in the example at the top of the page.

### Alignment

`align` is `left` (default), `center` or `right`. It aligns the tab group on the full-width line.

<Example name="tabs/Centered" lang="en" />

### Scrollable tabs

`scrollable` shows arrow buttons when the tabs don't fit on one row. The selected tab is scrolled into view. Without `scrollable` the tabs don't wrap, so use it whenever there are many tabs or long names.

<Example name="tabs/Scrollable" lang="en" />

### Controlled

`value` and `onChange` keep the selected tab in state, for example when the tab is stored in the URL.

## Content guidelines

- Give tabs short names of one or two words.
- Use parallel names: "Borrowing, Events, Rooms", not "Borrowing, See events".
- Keep the number of tabs low. With more than five, consider another structure.

## Accessibility

**The component handles**

- The tabs use the `tablist`, `tab` and `tabpanel` roles, and `aria-selected` marks the selected tab. A panel is named after its tab.
- The left and right arrow keys move between tabs and select them. The list wraps from end to start.
- The Tab key moves on from the tabs, so the tab row is a single focus stop.
- The selected tab is bold and underlined, not shown by colour alone. A focused tab gets the TREDS focus ring.
- The scroll buttons have Finnish default names.

**Your responsibility**

- Give `TabsList` an `aria-label` that says what the tabs are about.
- Give the scroll buttons names in the page's language with `scrollLeftLabel` and `scrollRightLabel` if the page isn't in Finnish.
- If a panel has no focusable content, the Tab key skips it. Make sure the panel's content can also be found in a screen reader's browse mode.

WCAG criteria: [1.3.1 Info and Relationships](https://www.w3.org/WAI/WCAG21/Understanding/info-and-relationships.html), [1.4.1 Use of Color](https://www.w3.org/WAI/WCAG21/Understanding/use-of-color.html), [2.1.1 Keyboard](https://www.w3.org/WAI/WCAG21/Understanding/keyboard.html), [4.1.2 Name, Role, Value](https://www.w3.org/WAI/WCAG21/Understanding/name-role-value.html)
