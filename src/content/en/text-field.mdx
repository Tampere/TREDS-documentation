# TextField

<ComponentBadges name="TextField" lang="en" />

A single-line text field for short answers, such as a name, an email address or a phone number.

<ComponentLinks name="TextField" lang="en" />

<Example name="text-field/Hero" lang="en" />

## When to use

Use a text field when the user types a short, single-line answer that can't be chosen from ready-made options.

**Don't use a text field when**

- the answer is longer than one line – use <ComponentRef name="TextArea" lang="en" />
- the user picks the answer from ready-made options – use <ComponentRef name="Select" lang="en" />, <ComponentRef name="RadioButton" lang="en" /> or <ComponentRef name="Checkbox" lang="en" />
- you ask for a date or a time – use <ComponentRef name="DateField" lang="en" /> or <ComponentRef name="TimeField" lang="en" />
- you need a search field with a search button – use <ComponentRef name="SearchField" lang="en" />

## Variants and situations

### Helper text

`helperText` shows below the label. Use it for the answer's format or anything else the user needs to know before typing.

<Example name="text-field/HelperText" lang="en" />

### Required field

`required` adds an asterisk after the label and the native `required` attribute to the field.

<Example name="text-field/Required" lang="en" />

### Error

`error` shows an error message and colours the field with the error colours. Say in the message what's wrong and how to fix it.

<Example name="text-field/Error" lang="en" />

### Disabled

`disabled` prevents typing. First consider showing the information as plain text instead, because a disabled field can't be reached with the keyboard.

<Example name="text-field/Disabled" lang="en" />

### Search icon

`showSearchIcon` adds a search icon at the start of the field. Use it with `type="search"` in filter and search fields that don't need a separate search button.

<Example name="text-field/Search" lang="en" />

### Clear button

`showClearButton` shows a clear button while the field has text. When the field's value is in state (`value`), clear it in `onClearButtonClick`. Return focus to the field at the same time, because the button disappears once the field is empty.

<Example name="text-field/ClearButton" lang="en" />

## Content guidelines

- Keep the label short and say what is asked: "Email", not "Type your email address here".
- Don't use placeholder text (`placeholder`) instead of a label or instructions. It disappears when the user starts typing, and its contrast is often weak.
- Say in the error message what's wrong and how to fix it: "Check the email address. It should look like name@example.com."
- Mark required fields consistently across the form.

## Accessibility

**The component handles**

- `inputLabel` is the field's `<label>`, so screen readers read it as the field's name.
- The helper text and the error message are connected to the field with `aria-describedby`, so screen readers read them with the field.
- An error sets `aria-invalid="true"` on the field.
- `required` sets the native `required` attribute. The asterisk is hidden from screen readers, which announce the requirement themselves.

**Your responsibility**

- Always give the field a visible `inputLabel`. If that isn't possible, give it an `aria-label`. Mantine's `label` and `description` props don't work: use `inputLabel` and `helperText` instead (#178).
- Set `type` and `autoComplete` on personal data such as name, email and phone number, so the browser can fill them in.
- Always set `clearButtonLabel` when you use `showClearButton`, because the button has no default name.
- Return focus to the field when the clear button is pressed. Otherwise focus is lost to the top of the page along with the button.
- An error message doesn't announce itself when it appears. When a form is submitted with errors, move focus to the first invalid field or to an error summary.

WCAG criteria: [1.3.1 Info and Relationships](https://www.w3.org/WAI/WCAG21/Understanding/info-and-relationships.html), [1.3.5 Identify Input Purpose](https://www.w3.org/WAI/WCAG21/Understanding/identify-input-purpose.html), [2.4.3 Focus Order](https://www.w3.org/WAI/WCAG21/Understanding/focus-order.html), [3.3.1 Error Identification](https://www.w3.org/WAI/WCAG21/Understanding/error-identification.html), [3.3.2 Labels or Instructions](https://www.w3.org/WAI/WCAG21/Understanding/labels-or-instructions.html), [3.3.3 Error Suggestion](https://www.w3.org/WAI/WCAG21/Understanding/error-suggestion.html)
